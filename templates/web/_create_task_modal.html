Loaded via HTMX (``hx-get`` from the global ``+`` button or the ``c`` hotkey) into ``#modal-root`` in ``base_app.html``. Architecture ============ The rail is a presentation layer over the same ``
`` the stacked version had. ``actaCreateTask()`` holds the state and *projects* it into hidden inputs with the old names (``status`` / ``priority`` / ``size`` / ``due_date`` / ``assignee`` / ``cycle`` / ``labels``), so ``_create_task_post`` parses exactly what it parsed before and never learned the selects are gone. Same split as the filter dock. The options come from ``build_create_task_data`` as one ``json_script`` rather than as markup: eleven rows of members and labels would otherwise be most of the dialog's weight, nearly all of it never opened. Behaviour kept from the stacked version: * ``Esc`` backs out of the open popover first and the dialog on a second press; the backdrop does not close it (shell wires both). * ``acta:task-created`` (window) → ``created()``: dismiss, or — after ⌘⇧↵ — reopen a fresh dialog on the same project. * Picking a project re-renders the whole dialog from the server so the member / label / cycle options follow the new workspace; every other field rides along through ``hx-include`` and comes back as ``pre_*``. * ``Open after create`` (persisted in ``localStorage``): ON → server returns ``HX-Redirect`` to the new task; OFF → ``204 + HX-Trigger: acta:task-created``. * Description: TipTap editor (same module the task-detail page uses, via ``[data-description-editor]``). {% endcomment %} {% block root_attrs %} x-data="actaCreateTask()" @acta:task-created.window="created()" {% endblock %} {% block panel_class %}acta-ctm-panel{% endblock %} {% block panel_attrs %}x-init="$nextTick(() => $refs.title?.focus())"{% endblock %} {% block title %}
