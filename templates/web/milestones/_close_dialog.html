{% load i18n %} {% load lucide %} {% load web_extras %} {% comment %} Closing a milestone that still has unfinished work (design "AppMilestone", artboard 05). Expects ``milestone``, ``open``, ``done``, ``total`` and ``close_targets`` from the detail context. This is the moment the feature either feels careful or sloppy: the date was reached or missed, which is a fact about the date, but the work that did not make it is still work, and it has to land somewhere on purpose. So the dialog asks — move it to a milestone that covers it, or detach it — and says what each choice does before it happens. A target whose scope covers none of the open work is shown disabled rather than hidden: the absence is the answer. {% endcomment %}
