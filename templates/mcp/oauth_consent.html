Reached from ``apps.mcp.oauth.authorize`` with the client and the already-validated redirect URI in context. Everything the authorize request carried is echoed back through hidden fields so the POST can be re-validated from scratch: the GET that rendered this page proves nothing about the POST that follows it. ``client_name`` comes from the client's own registration and is therefore attacker-controlled text — it is rendered as plain text (never marked safe) and framed as a claim ("says it is"), because a connector can call itself anything it likes. The signed-in account is named, and can be swapped without leaving the flow: a client opens this page in the default browser, so the session waiting here is often not the account the person meant to connect. The "different account" button is a second submit on the same form, aimed at ``switch_account`` through ``formaction`` — one set of hidden fields serves both destinations, since nested forms are not a thing. {% endcomment %} {% block title %}{% trans "Authorise connection" %} · Acta{% endblock %} {% block auth_main %}
